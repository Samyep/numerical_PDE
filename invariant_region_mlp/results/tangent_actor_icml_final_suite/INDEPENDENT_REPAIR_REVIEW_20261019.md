## Independent artifact audit

I opened all 28 primary rows in `MAIN_RESULTS.csv` and all 40 repaired primary
rows in `ACCURACY_COMPUTE_FRONTIER.csv`. For every row I independently:

1. loaded the frozen source prediction NPZ and the canonical paired NPZ;
2. recovered the selected prediction array from the source artifact;
3. compared it exactly with the canonical `prediction` array;
4. hashed numerical `t,x` and `truth` arrays with dtype and shape boundaries;
5. hashed the source and canonical files byte-for-byte; and
6. recomputed RMSE, relative L2, bias, and MAE.

All 28 main rows and all 40 frontier rows passed. The maximum absolute
difference between a recomputed metric and its CSV value was zero in the
independent calculation. The maximum difference between a preserved
`raw_value_*` field and the corresponding pre-repair CSV value was also zero.
All 68 files in `paired_predictions/` have finite, shape-compatible
`t,x,truth,prediction` arrays. Every one of the 28 `main_`/`frontier_`
counterpart pairs is numerically identical.

Of the 28 main source NPZs, 23 embed `t,x`, three historical Tangent-Actor
artifacts embed exact test indices into their frozen banks, and two native
OU/GMM DPI/PINN artifacts contain predictions only. The last two can therefore
be tied to the common bank only through their frozen runner contract and
prediction length; this is a residual provenance limitation, not an observed
pairing discrepancy.

## Verification guard and tamper test

`verify_paired_banks.py` cannot pass from matching CSV strings alone. It opens
each canonical NPZ, checks finite arrays and shapes, recomputes numerical bank
and truth hashes, recomputes all four metrics, checks the canonical file hash,
and checks the frozen source file hash. It then requires one actual bank hash,
truth hash, and state count across the four methods.

`test_paired_banks.py` first constructs a passing two-method case, then changes
an actual time array while leaving every CSV metadata string unchanged. The
audit changes to FAIL. I ran the complete suite package with:

```text
/sw/user/python/miniforge3-pytorch-2.10.0/bin/python -m pytest -q \
  invariant_region_mlp/experiments/tangent_actor_icml_final_suite
```

Result: `24 passed` in `38.81s`. An independent in-memory call to
`verify_paired_banks.audit(MAIN_RESULTS.csv, 100)` also returned PASS for all
seven PDEs and all 28 primary method rows.

The guard has one hardening opportunity: it verifies the source file's hash but
does not itself compare the canonical prediction values with the prediction
array extracted from that source, nor does it reload the named authoritative
bank/reference source. This review performed both comparisons for the current
artifacts. Adding them to the recurring verifier would reduce reliance on the
repair constructor and CSV provenance.

selection path. It reads source NPZs, writes new files only under
`paired_predictions/`, and rewrites derived tables/audits. All 28 canonical
main predictions are exactly equal to the selected prediction array in their
frozen source NPZ.

Filesystem times provide an additional independent check: the 28 source
predictions span 2026-10-16 21:14 through 2026-10-19 04:29 CDT, and the 22
checkpoints referenced by the main rows end at 2026-10-19 04:29 CDT. The

files at 15:50 CDT. No source prediction or referenced checkpoint has a repair-
time modification. The artifacts are ignored by Git, so there is no
pre-repair Git blob against which to prove byte identity; the current source
prediction SHA-256 values are now recorded, while the checkpoint-preservation
conclusion additionally relies on the write-path and timestamp evidence.

Future Tangent-Actor runners (`run_standard_actor.py`, `run_joint_actor.py`,
and `run_mlp_failure_actor.py`), the shared DPI/PINN runner
(`official_dpi_transfer.py`), and the SDGD runner (`sdgd_transfer.py`) now emit:

- `test_bank_array_sha256` for numerical `t,x`;
- `test_bank_file_sha256` for the NPZ container;

`test_bank_sha256` remains as a compatibility alias for the numerical array
